## Workflow — GitHub issues are the backlog
- Every task the user names becomes a GitHub issue. Create it immediately with `gh issue create`, don't batch them up.
- Labels: `de-clone`, `ui`, `bug`, `data`, `legal`, `infra`. Reuse them; only add a new label when none fits.
- An issue body states what is wrong, the measured evidence, the files involved, and its dependencies on other issues. No vague one-liners.
- Close issues from commit messages (`Closes #4`) so the backlog does not drift from the code. Qualifying it does NOT scope it: `Closes #23 for web/main.ts` still closed all of #23 on push, and its second half had to be reopened by hand. When a commit does part of an issue, write `Refs #23`.
- `tasks/todo.md` is scratch for the current session only. GitHub issues are the durable backlog.
- **Several sessions share ONE working tree AND ONE INDEX, so commits are made with `git commit --only <paths>`, never from the staging area.** On 2026-09-06 a walk session ran `git add data/combos.json docs/phase0/walks/<file>` — path-scoped, as it should — and its `git commit` still swept four files another session had STAGED but not committed (src/combos.ts, src/matcher.ts and their tests), because `git commit` takes everything in the shared index. `git add <paths>` does not prevent that; `git commit --only <paths> -F -` (or `git commit -o <paths>`) does, because it commits exactly those paths whatever the index holds. Each session owns named paths (a walk: `data/combos.json` + `docs/phase0/walks/`; UI: `web/`, `src/`, `test/`; synergies: `data/synergies.json` + its test) and commits only those with `--only`; never stash or reset someone else's changes; before pushing, `git fetch` and push only when `origin/master` is an ancestor of `HEAD`.

## Data
- Card text comes ONLY from Riot's gallery content API via `scripts/build-cards.mjs`; never from RiftScribe or other mirrors (they drop Equipment `effect` text and have no ban data).
- Errata is a dated overlay in `data/errata.json`; the build must fail if a find-string stops matching exactly once per printing. The one tolerated exception is a reprint that already carries the new text (Sona VEN-SP2, Void Burrower SFD-243): the build skips it. Riot's gallery API lags its errata pages by months, so after each Riot errata post, transcribe it into the overlay (audit of all four pages done 2026-09-03, #17).
- Legality is hand-transcribed from Riot's Rules Hub into `data/legality.src.json` (names) and resolved to codes at build time; it is format-scoped and entity-typed, never a boolean on the card.
- Match cards on base codes (`OGN-212`), never on names. Names are only for parsing pasted decklists.
- Card `type` is exactly one of `unit`, `spell`, `rune`, `gear`, `legend`, `battlefield`. **Equipment is not a type** — it is `gear` carrying the `Equipment` tag, so any filter on `type == "Equipment"` returns zero rows silently. Tags ride on every card in `cards.json` (`tags: string[]`) as well as in `data/corpus_flat.txt`, and a synergy predicate can stand on them alone — `Mega-Mech` is a Mech with no rules text. Two helpers (`UNL-T04 Buff`, `UNL-T08 XP Tracker`) carry an empty `type`.
- All 94 legends are named as bare epithets in the gallery (`Deceiver`), while Riot's own errata pages and players write `LeBlanc, Deceiver`. `resolveName` therefore retries on the text after the first comma, and `normalizeName` accepts both `- Starter` and `, Starter`. A third retry (2026-09-06, #86) handles Riot's own inconsistency: the same champion is printed with two heads — `OGS-004 Yi, Meditative` / `OGS-009 Yi, Honed` in the starter, `UNL-059 Master Yi, Unstoppable` / `UNL-113 Master Yi, Tempered` in Unleashed — and the "Top Decks" articles write the long head for all four, so `resolveName` retries with the last word of the head + the epithet, ONLY when the head is a tag the pool prints (eleven tags are multi-word; `Master Yi` is the only one whose last word heads a name). Verified 2026-09-04: no card name collides with another card's `X, Y` suffix, so the fallback can only rescue, never mislead.
- Base codes are NOT all `SET-NNN`: 22 are `SET-T0n` tokens, `SET-R0n` runes and `VEN-SP1`–`SP6`, and those last six are real playable cards (Kai'Sa, Sona, Ahri, Sett, Ezreal, Lux). A regex like `^[A-Z]{3}-\d{3}$` drops them silently; the shape that works is `[A-Z]*\d{1,3}[a-z*]?` and BOTH suffixes are load-bearing — 45 printings are alt-arts whose code ends in `*` and 102 end in a lower-case `a`; the two families coexist. Any normalisation must be CASE-INSENSITIVE end to end: until 2026-09-06 (#87) `resolveCode` upper-cased the input and then `baseOf` trimmed with a case-sensitive `/[a-z*]$/`, so `UNL-113a`, `UNL-113A` and `ogn-007a` all failed — 306 of the 3,567 spellings of the pool's own codes were being dropped, including Riot's gallery spelling; a test now sweeps all 1,189 codes in three spellings. riftbound.gg writes the alt-art suffix in upper case (`UNL-113A`). Its full dialect (#90, 2026-09-06, measured on 452 lists / 12,150 lines): `-STAR` is exactly the 45 alt-arts the gallery writes with `*` (one to one, normalised to `*`); `-P`, `-P2`, `-P-Champion` are PROMOS (promo=1 in dotgg's index: Nexus Night, Judge, Release Event, Summoner Skirmish) that Riot's gallery does not carry at all, so they resolve to the base code; `OGN-263-a` is the one id that hyphenates the variant letter. And **runes are printed only under Origins and reprinted in Vendetta — there is no `SFD-R0x` or `UNL-R0x` in the gallery**, so a Spiritforged or Unleashed rune line is an alias in `RUNE_ALIAS` (`src/cards.ts`), verified by name (R01 Fury, R02 Calm, R03 Mind, R04 Body, R05 Chaos, R06 Order in all three sets), not a suffix to normalise; without the Unleashed row a list lost its whole rune deck (696 of 775 rune lines). Before: 1,154 lines lost; after: 0. Audited 2026-09-04 (#14): every code regex in the repo was run against all 1189 codes, and the one failure was the TTS line guard in `src/deck.ts`, which used `[a-z]?` and so lost EVERY code on any dump line containing an alt-art.
- Anomalies in Riot's own text (bracket-less keywords, a dangling `[Effect] 1`, wrong tags, double periods) are REGISTERED in `docs/data-anomalies.md`, never normalised. They must never go into `data/errata.json`: that overlay's find-string failure is the only mechanism keeping our text honest, and spending it on a cosmetic typo would hide the next real errata behind it. What IS ours to fix is the HTML decoding in `stripHtml` — Riot ships `p`/`br`/`ul`/`li` and `&gt;`/`&quot;`, and two decoding gaps (undecoded `&quot;` on 12 cards, modal `<li>` modes glued into one clause on 15) were fixed on 2026-09-04.
- **Deck construction (#43, 2026-09-06) — three data facts a builder cannot derive from the code.** Riot's gallery carries NO Signature marker (0 hits in `cards_full.json`, no tag) — `checkBuild` therefore reports `pass | fail | unknown` per rule, never a boolean, for rules the card data cannot see. 103.2.d (max 3 Signature cards) and the Signature half of 103.2.a.2 stopped being two of those on 2026-09-06 (#103): two independent mirrors (Piltover Archive's `card.super`, dotgg's `supertype`) agree on the same 51 names, transcribed by name into `data/signature.src.json` and resolved to exactly one base code each in `scripts/build-cards.mjs`, which fails the build on a name resolving to zero or 2+ bases; `Card.signature: boolean` rides in `cards.json`. `checkBuild` now scores 103.2.d.1 (≤3 total, regardless of name — checked even with no legend, since it does not need one), 103.2.d.2 (each carries the legend's champion tag) and 103.2.d.3 on the Chosen Champion (a Signature card, even one whose tag matches, can never be Chosen Champion — Tibbers is the rule's own worked example). The champion tag IS derivable: a tag T is a champion tag when a card named `T, <epithet>` exists — all 127 legend printings yield exactly one, including the four with 2–3 tags (VEN-155 Yordle + Kennen → Kennen); pinned by a test over the whole pool, which also pins the 51 Signature base cards and their one champion tag each. And 103.2.b (3 copies) is a MAIN DECK rule: 103.3.b keeps the Rune Deck apart and 103.4.c covers battlefields, so counting runes against it declares EVERY legal deck illegal (six Mind Runes). The nine rules are quoted verbatim in `docs/phase0/walks/2026-09-06-deck-construction-rules.md`.
- Tokens, runes and the two typeless helpers stay in `data/corpus_flat.txt` on purpose: 79 corpus lines tell you to play a token without printing what it does, and rule 187 plus the token's own row is the lookup a rules walk needs (the R25 ruling turned on `UNL-T05 Gold`'s text). An empty `type` renders as `-`, not as a blank column.

## Combos
- `data/combos.json` is AUTHORED. `status: verified` requires a hand-walked loop against card text + Core Rules with sources; agent output enters as `candidate` until a human reviews it.
- Every combo carries a class: INFINITE (walked, unbounded), BURST (**one** scoring event reaches 8), CHAIN (reaches 8 across **several** scoring events, without the opponent taking a turn in between), ALT_WIN (a card that literally says you win), or ENGINE. Never label INFINITE without a "repeat" step. CHAIN was added 2026-09-04 (issue #20) for the three Time-Warp-chained and double-Conquer finishers that reach 8+ but not in one event: labelling them ENGINE would have been false, since they win. The class is a plain string in the UI (`c.class.replace("_", " ")`), but it is typed in `src/types.ts` and ranked in `src/combos.ts` CLASS_RANK plus the sort orders in `web/graph.ts` and `web/main.ts` — all five must be updated together.
- Do not accept structural verdicts from agents ("no X exists in the pool") without walking the validation set first; the first hunt's "no infinite combos" was wrong.
- Authoring traps the 2026-09-03 REFUTE passes caught repeatedly, check every new entry against them: entering an EMPTY enemy battlefield is not an attack (Assault and "When I attack" need the Attacker designation, which exists only inside a Combat with a garrison: 807.1.d, 383.4.e, 461); Energy added in Awaken or the Beginning Phase is lost when the Rune Pool empties at the Main Phase start (167); a Repeat gives no window to re-exhaust a resource permanent between executions (429.3, R21); Temporary tokens die before Scoring, so they never Hold and never see a Main Phase start (816.1.b) — but that trap does NOT stop a Temporary body being COUNTED by an ability that fires at the same instant, because 816.1 makes Temporary a Triggered Ability and 383.3.d lets the player controlling both abilities order them (settled 2026-09-04 for `gutter-palace`, which had it filed as an open reading); Gold tokens are printed "exhausted", but Renata Industrialist overrides that and they enter ready (R25 = A); recycling a rune for Power sends it to the Rune Deck (161.2.b), so Ekko readies only what is still on the board; a recall is not a move (456) and does not change state (458). A `would die` shield of the heal / exhaust / recall family ERASES the Deathknell of what it saves: 808.1.d.1 removes the triggered ability from the chain when the permanent never reaches the Trash (found 2026-09-06 on `soraka-fiora-loop-shield`, whose replacement has no `may`, so it also switches off the Deathknell of any friendly body under 4 Might that dies at the base). **A token never reaches the trash**: 186 / 186.1 — tokens exist only on the board or the chain and cease to exist the moment they enter any other Non-Board Zone — so a `Recycle 1 from your trash` (Vi, Destructive) can never pick a dead Recruit, Gold or Bird, and a loop that counts on recycling its tokens is wrong on its face; 416.6 makes the recycling player choose WHICH cards a `Recycle X from [Zone]` takes, and it does not target them (found 2026-09-06 walking #62's contradictions). And the shorter form of the same trap, rule 185 — **"Tokens are not cards."** — with 416.1 (Recycling is defined on CARDS only): a line that recycles a token, or feeds a `Recycle N` cost with tokens, is refuted on its face; two sources in #62 believed Mech tokens were recycle fuel. **A Recall comes from ANYWHERE** (455: "relocated from anywhere to its Base without it being a Move"), so a save-by-recall like Guardian Angel also switches off any `While I'm at a battlefield` text on what it saves.
- A BURST entry must reach 8 **with the quantities it declares**, and the class must match `terminatesIn`. Check the entry's own formula against its own `uses` before authoring or promoting: the 2026-09-04 audit of all eleven BURSTs found four that failed this. `ahri-blue-sentinel-hold`, `blue-sentinel-trinity-force-hold` and `ivern-sentinel-hold` each declared a board their own printed formula resolves to 7; `tryndamere-brambleback-conquer` declared one worth 4, which its own REFUTE note had already flagged in 2026-09-03 without the fix ever being applied; and `renata-time-warp-ekko-refresh` claimed BURST while its own `terminatesIn` described points spread over two turns (reclassed ENGINE). A REFUTE verdict in `notes` is not a fix — grep for corrections that were diagnosed and never applied.
- Recycle budget is the real currency of an INFINITE loop, not the 3-copy deck limit. Recycle (416.1) puts cards on the BOTTOM OF THE DECK, so a spell consumed every pass is fine as long as the entry can name the recycle slot AND the matching draw that bring it back. The verified `lux-infinite-energy` engine saturates its 4 draws per pass and leaves EXACTLY ONE spare Forge recycle slot (Forge recycles 3 of its 4; Ekko's Deathknell recycles itself). REFINED 2026-09-04 by the joint ledger on issue #21 (`docs/phase0/walks/2026-09-04-loop-budget-ledger.md`): the scarce resource per pass is **draws, not slots**. Both pass types leave spare slots and ZERO spare draws — the Energy pass leaves 1 slot, and `lux-infinite-power` is a second, different pass that leaves 2. And the draw is purchasable: Renata Mastermind's `1 Energy + 1 Mind: Draw 1` carries NO exhaust in its cost (unlike her Score ability beside it), so extra draws are unlimited and an extra cycled card costs 1 Energy + 1 Mind Power ≈ 10 Energy at the 9-Energy-per-Power rate. No payoff in the catalogue consumes a card per PASS; they consume one per point, and a point costs ~50 passes, so ~50 spare slots accumulate per point. The three Renata routes are alternatives because they all do the same job (ready Renata to score again), not because the engine cannot feed two. Do not re-derive any of this as a copy-limit bound. **Equipment that copies text COMPOSES, it does not add** (settled 2026-09-06 on #45): 434.1.c gives the Top-Most Card ALL the Effect Text of ALL its attached cards; 477.2.c appends that text in Layer 2, 479.1 finds no dependency between two copies that each alter the other, 480.3 falls back to timestamp order (attach order), and 476.1 applies each effect only once across all sequences — so v Svellsongur on one unit yield 2^v instances, not 1+v, and 476.1 is why R6 = A opens no recursion. `svellsongur-copy-hold` went from 11 to 17 points on the same five cards and its ceiling from 26 to 41. Companion fact from the same walk: an ability worded `When I conquer or hold` is BOTH a Conquer Effect and a Hold Effect (823.1.b, 823.1.c.1 spell it out for Hunt), so Reckoner's Arena doubles it twice — `ivern-arena-sentinel-hold` reaches 9 for 20 Energy + 2 Power. Always count the [Equip] costs and the Power: two published "18 Energy" figures had counted neither. **A legend is not at a location** (107.4.b: the Legend Zone "is not a location"), so Reckoner's Arena's "here" and Svellsongur's attach never reach a legend's own `When you conquer` text — the whole "legend + Arena" family is dead on arrival (#47, 2026-09-06). And 206 / 206.1 make cost-triggered abilities (Lady of Luminosity, Curator of the Sands — both are the worked examples) fire on the PRINTED or BASE cost, so discounts and free plays do not switch them off. REFINED by #47's walk (2026-09-06): that holds for CARDS (206 has no exception), but 206.1 for ABILITIES says "unless otherwise specified", and Empower specifies — 827.1.c.3: cost-altering text "is taken into account when determining a card's Empower cost for any reason" — so an Empower discounted to 0 does NOT fire a cost-threshold trigger; the "Empower discounted to 0 that still triggers on its base cost" family is dead. Two more facts from the same walk: Heimerdinger copies ACTIVATED abilities with exhaust in the cost, never a "you may exhaust me to…" (that is a Triggered Ability, 383.1, and triggers are not copied); a token with no printed destination goes to the base OR a battlefield you control (355.2.a) — no walk needed; and "Legend" in card text means the legend in the Legend Zone (355.9.a.4), which is how Heimerdinger reaches a legend's exhaust ability. **Tokens are born at the base, and points are scored at battlefields** (#48, 2026-09-06): of the 49 cards that create unit tokens, 18 say "at your base" outright, 13 say "here" (a battlefield), and 18 name no destination (355.2.a: base, or a battlefield you control). Exactly ONE card in the pool relocates tokens in bulk — `SFD-177 Azir, Sovereign`, "When I attack, you may move any number of your token units to this battlefield" — so the bottleneck of every token line is the walk to the battlefield, not the token count. And there is NO window to add a body at the instant of the Hold: 315.2.b.2 puts the Hold in the Scoring Step of the Beginning Phase, 312.2.a gives priority only in the Main Phase, and 383.2.a.1 measures the condition when the trigger is placed — the seven for the Plaza must survive the opponent's whole turn. Four more from the token walk (#48, 2026-09-06): **"here" is read at execution** (359.3.f.2), so an effect that plays tokens "here" twice on two landings leaves each batch where it fell — two Signpost/Accelerate landings do NOT stack on the Plaza, only the last one counts; **the Plaza count includes the body that conquered it** — 355.2.a needs you to control the Plaza before the tokens are born and 323.6 needs it still occupied, so Corina's line is 8 there, not 7, and `flurry-of-feathers-grand-plaza-win` already counted that way; **Gold born from a Hold is next turn's Power** — Awaken (315.1) precedes the Scoring Step, the Gold token's ability costs an exhaust (187.5), so a Hold-made Gold enters exhausted unless Renata Glasc, Industrialist is out (R25 = A); and **check 103.1.b.1 before folding a card into an existing entry** — #48 proposed Chemtech Cask (Mind) inside an Order/Chaos entry, impossible by Domain Identity. **Stun lens (#61, 2026-09-06):** ZERO cards exhaust an enemy unit (full inventory of the verb, 32 uses; Conscription steals first), and exhausting is not stunning — "exhaust" appears in no combat rule 461–466, 464.2.c.3 and 465.2.b do not filter by state, so an exhausted defender fights with its full Might; what makes a stunned unit PAY is not 423.1.b (which only removes its contribution to combat damage) but 423.1.c read with 710: it still needs damage equal to its full CURRENT Might to die, which is why Leona Zealot's −8 matters (corrected by #89's walk). 423.1.a.1 "A Stunned Unit can not be Stunned again" plus 423.1.a.2 (cleared only at cleanup 3d) means no stun engine can be INFINITE; no card pays points for a stun, so the lens yields no BURST/CHAIN/ALT_WIN; stun is Calm + Order (21 of 29 lines, none in Mind or Fury). A hidden 0-Energy stun caps at one per CONTROLLED battlefield per turn (811.1.b) and must target there (811.1.d.2). **The mechanic lenses are NOT all swept** — the 2026-09-06 tournament pass (#89) showed at least four more with real play behind them: DISCARD and recursion from the trash (35 `discard` + 47 `from your trash` lines; two of #89's biggest candidates live there, and 422.1.b makes "When I am discarded" execute AFTER the discard, i.e. from the trash), BUFF (49 lines; the 258-list Boss + Showstopper + Sett group comes from it and sits on 808.1.d.1), Might REDUCTION (Leona Zealot's −8 to stunned units is in no entry and corrects #61's coverage; Fox-Fire and Ahri's −Might), and "cards played this turn". **Ready lens (#56, 2026-09-06):** "enters ready" is not a ready — 143.4 makes units enter exhausted and 415.1 defines Readying as marking a Game Object already on the board, so the 48 "enters ready" cards can never give an exhaust back; only 16 cards in the pool ready something other than themselves. A legend IS on the board (107.4.c, "The Champion Legend here is a Game Object") even though it is not at a location (107.4.b), so readies reach it: five cards ready your legend (SFD-039, SFD-210, OGN-162 Miss Fortune, VEN-068 Jayce, Brilliant Inventor's "ready something besides me that's exhausted", and OGN-111 via Heimerdinger's copy) — #56's walk added Jayce after #56's hunt had counted four. Five cards ready gear (VEN-149, VEN-150, SFD-221, OGN-162, VEN-068) — a `grep` that swallowed an adjective once published "the ONLY card that readies gear" inside a verified entry; when a note claims uniqueness, grep the whole pool with `-i` and the bare word before shipping it. **Movement lens (#58, 2026-09-06):** `[Ganking]` is NOT an extra move — 810.1.c.3: "It does not give additional abilities or activations of Movement, only new options for the Standard Move" (37 corpus lines carry it). 144.4 restricts destinations and 420.3.a puts the exhaust cost ONLY on the Standard Move, so a move BY EFFECT goes battlefield to battlefield without Ganking and moves EXHAUSTED units — that is the mechanical name of the token bottleneck from #48 (`UNL-045 Forgotten Signpost` does it for 0). And no entry of the catalogue moves an ENEMY unit: emptying the garrison wins the combat with no damage step (465.1 needs both Attacking and Defending units for the damage tasks; 466.5.d makes establishing Control a Conquer), while 323.9 marks no Combat when no opposing units are present, so the "empty battlefield is not an attack" trap is respected — it is a Conquer without an Attacker. REFINED by the #58 walk (2026-09-06), which found the rule the hunt had missed: **323.10** ("If Units of two opposing players are no longer present at a Battlefield that has a Combat Staged **before it has opened**, the Combat will cease being Staged") opens a THIRD route — evacuate a garrison after the Combat is staged and it un-stages itself, leaving only the Showdown, so 348.2.a / 348.2.a.1 give Control and a Conquer with no damage and no Attacker designation. **Only a Triggered Ability reaches that window**: while its trigger sits on the chain the state is Neutral Closed (310.2) and 323.13 (which needs a *Neutral Open* State) cannot open the Combat, whereas after a plain move the very next Cleanup stages the Combat (323.9) and opens it (323.13) with no gap — and 155 bars a spell without [Action]/[Reaction] from a Showdown. So an evacuation SPELL must be cast **before** the entering move, never after; `charm-evacuate-conquer` and `faefolk-challenger-forced-attacker` are two different lines for that reason, not two versions of one. Companion facts from the same walk: 323.6 strips a player's Control the moment their last body leaves (a *staged* Combat is not an *ongoing* one), so pulling the garrison off makes the battlefield uncontrolled — i.e. **open** — in the same Cleanup; 190.3.a / 190.3.a.1 / 450 key Contested on the moved **unit's controller**, not on who caused the move, so dragging an enemy body onto your battlefield makes THEM the Attacker on YOUR turn (464.2.c.1); and 464.2.e.1 puts the Defender's triggers on the Combat Chain last, which by 340.1 makes them resolve FIRST. Two paraphrases to distrust: `447.2` is only the definition of Destination (the invalid-destination list is 447.2.a / 447.2.b), and `190.4.c` ends "unless there is a Combat or Showdown ongoing there", a clause the #58 issue body dropped. `SFD-079 Bard, Mercurial` is the pool's only bulk mover of units of ANY kind (Azir Sovereign moves only tokens, and needs an enemy garrison to attack) and it needs the opposite board: an UNCONTROLLED battlefield, which 190.1 makes both of them at the start of a Duel. REFINED AGAIN 2026-09-06 by the #44 walk: **every deck has a free floor of 2 Power per turn**, so measure any new Power source against it, not against zero — 164.2.b (`Recycle this: [Reaction] — Add [C]`) carries no exhaust, so a rune already exhausted for Energy still recycles for Power; 161.2.b sends it to the Rune Deck, not the Main Deck; and 315.3.b / 430.4.a channel 2 back every Channel Phase before the Main Phase. The "12 recycles per game" ceiling #44 assumed does not exist. Seals produce per TURN and loops spend per PASS, so the ~9 Energy per Power rate for a loop stands. The extra cycled card costs 4 Energy instead of ~10 only when a Forge recycle slot is spare (Forge is `Recycle up to 4`), which only the Power pass guarantees: the Energy pass has one spare slot and the card itself eats it. **Exception, found 2026-09-06 on the Dragonstorm ledger (#46):** `SFD-117 Ancient Henge` — `exhaust: [Reaction] — Pay any amount of Energy to [Add] that much rainbow` — converts Energy to Power 1:1 with NO cap per activation, so a loop that re-plays a Henge every pass (Detonate kills it, Vi recycles it, Show of Strength draws it back; gear enters ready since 143.4 exhausts only units) makes Power stop being the scarce currency: its ledger is Energy-only, and the ~9 Energy per Power rate does not apply to it. The Henge is E2 P1, so the FIRST pass must be primed with the Power the conversion will later supply. **Burn Out, the three rules every draw line must respect (#59, 2026-09-06):** drawing past the deck burns out (431.1.a) and so does milling — `[Burn N]` or any "put cards from your Main Deck" past the deck (431.1.b) — but LOOKING or REVEALING past the deck never does (431.1.c: "does not Burn Out"), so reveal-and-draw is the only free family inside a loop that runs with the Main Deck empty. The "0 spare draws" of the Lux ledger is a WALL, not a slack to widen: with the deck empty, the 4 draws and the 4 cards that come back are balanced on purpose and a fifth draw is 431.1.a, a point for the opponent (194.1.d) — every extra draw source needs a recycled card riding with it. A draw with exhaust in its cost is useless inside a loop (every pass is the same turn) and no repeatable gear-reader exists, which kills 13 of the 102 uncatalogued draw cards including Garbage Grabber. **Discard/trash lens (#95, 2026-09-06):** a card's own trigger works from the trash — 385.1/385.2 (Triggered Abilities outside the Board self-describe their context; 385.2's worked example is the "return this from your trash" wording of Super Mega Death Rocket!) — and neither 385 nor 422 was cited by any entry before. A Burn Out does more than cost a point: 431.2.b RECYCLES YOUR WHOLE TRASH into the Main Deck, which erases the currency of every trash line (Rhasa, Dr. Mundo, Last Rites, Shadow Assassin) and kills mill-kill outright — 431.3.a says repeated burning wins, but the pool has two cards that mill the opponent (VEN-002 once a turn, VEN-114 once) and the first Burn Out refills their deck. Looking and revealing never burn, not even the zone change that follows (431.1.c.1), so "look at 3, keep 1, trash 2" (VEN-156) is the only Burn-Out-safe trash filler; the eight `[Burn N]` fall under 431.1.b and do burn. ## Synergies (#22)
- `data/synergies.json` is a SEPARATE file and must stay separate. `combos.json`'s whole value is that every row in it was walked by hand; a text-matched row in there destroys that invariant.
- The unit is a PATTERN: one `anchor` base code plus a `partner` predicate over the pool. The rule is hand-verified once and carries `basis.rules` (Core Rules paragraphs), optional `basis.readings` (R-numbers from issue #11) and `basis.combos` (the verified entries it was extracted from). The instances are text matches. **Regla verificada, instancias por texto** — the UI says so in its own words and never presents a pair as a combo.
- **Print the whole match list and read it before shipping a rule.** `npm run synergies` prints every list, `-- --match` prints only the fragment each predicate caught, `-- <id>` narrows. A rule whose list you cannot read end to end is written too loosely; `test/synergies.test.ts` caps a rule at 150 matches for that reason.
- What the predicates are allowed to lean on: 383.4.c.1 and 383.4.d.1 give `"When I conquer…"` / `"When I hold…"` as the standard wording of those trigger categories, and 823.1.b makes [Hunt] both. That is why the hold and conquer predicates are honest rather than guesses.
- False positives found by reading the lists, and the shapes they come in — check any new rule against all four: a **nested quote** (Relentless Pursuit and Zed, From the Shadows carry a trigger written for another permanent inside their own text); a **second trigger that is a no-op** (Blitzcrank returns himself to hand, Hallowed Tomb needs an empty Champion Zone); a **doubled drawback** (Vaults of Helia, Sigil of the Storm); and a **condition that cannot be met on the other event** — 383.4.g.1 says an ability whose non-conquer parts are unfulfilled never reaches the chain, which is what kills Tryndamere, Sivir, Yeti Brawler, Yone and Swain under Reckoner's Arena. Record each as an `excludes` entry with its reason; never drop one silently.
- Tokens and the two helper cards are filtered out of every list (`domains.length === 0 && !type.includes("battlefield")`), since a decklist can never hold one. An anchor banned in every format fails validation — that is how `stealthy-pursuer-move-triggers` was caught.
- **A keyword lens opens with `grep -i <word>`, never with `[Keyword]`.** The bracketed form misses
  every card that writes the mechanic in prose: 8 cards say `empower`/`disempower` in lower case with
  no brackets and 4 of those are legends, so a `\[Empower\]` sweep silently skipped the legends of
  the family it was hunting (#34, 2026-09-05). Open wide with `-i`, then close by reading the list.
- **A battlefield you provide starts UNCONTROLLED, so its text is off until you take it.** 190.1:
  *"Control is established over Battlefields through the course of play."* 190.6.d closes it: *"If the
  battlefield has no Controller, 'you' refers to no one, and all such instructions are ignored."* The
  project had cited 190.6.d for R8 but never its second sentence. So a `While you control this
  battlefield` discount is NOT a deckbuilding freebie — walking a body there and establishing Control
  (466.5) is part of the entry's cost. Six battlefields print that wording; only SFD-211 Marai Spire
  is in the catalogue, and `ezreal-marai-spire-free-repeat` says so in its own notable (2026-09-05).
- **A battlefield is drawn at random, and only in some formats, and you cannot stack copies of it.** 485.4.a: a
  player provides three and only 1 is used; **485.5 and 487.5 say "randomly selects"**, while **486.5 says only
  "selects"**. So two of your battlefields never share a board (#33 fixes the synergy layer on this), and a
  battlefield-dependent combo is not certain to come online. Bringing 3 copies of the same battlefield is NOT a
  way out: **Core Rules 103.4.c** ("Cannot include more than one of a Battlefield of the same name when there
  are more than one required for the deck") and **Tournament Rules 402.1** ("exactly 3 battlefields each with a
  unique name") both forbid it. Issue #35 (2026-09-05) was opened believing the Core Rules were silent on this;
  they are not — 103.2.b is the Main Deck cap, the battlefield cap is three paragraphs further down. Every entry
  that needs a specific battlefield states this in `prerequisites.notable`, per format.
- A rule that matches most of the pool is a fact about the pool, not a pairing. "Retreat replays any play effect" measured 132 and was narrowed to play effects that leave another permanent behind (14).
- UI lives in the deck panel **below** "What to add", so #18 keeps the placement the user chose.

## Legal posture
- No ads, no donations, no meta stats (play/win rates), no combo *execution*, exact Riot disclaimer text from `docs/plan.md` §1.
- **Do not copy LOOPLINE.** It is the reference for *what a combo route map does*, never for how it looks or what it calls things. Copying its colour tokens, wordmark lockup, nav labels, headings or column labels is out of bounds — the 2026-09-02 build did exactly that and had to be reworked (issues #1–#3).
- Before shipping any UI string, check it is not lifted verbatim from the reference.

## UI — visual identity

Same file pins the one focus ring — `:focus-visible { outline: 2px solid var(--accent) }`, since Chrome's default is a light blue that appears nowhere else here — and allows `outline: none` only where another element draws the focus (the segmented control's label, the SVG node's frame).

- **The site lives at `https://riftcombo.app`** (bought through Vercel on 2026-09-05, #42; renewal US$15/yr,
  Vercel nameservers). `www.riftcombo.app` and `riftcombo.vercel.app` answer 308 to the apex, and that
  redirect is a **project-domain setting** (`PATCH /v9/projects/<id>/domains/<host>` with
  `{"redirect":"riftcombo.app","redirectStatusCode":308}`), not a `vercel.json` rule: a host-matched
  `redirects` entry in `vercel.json` was tried first on 2026-09-05 and never matched on a Git deploy.
  The old host stays in the Supabase redirect allow-list; every link, `site_url` and doc names `.app`.
- The hosted Supabase project is `bpbwsimgiyxzaorunqeo` in `us-east-1`, the region iad deploys to.
  Its **anon key is public by design** and rides in `public/app.js`; what keeps one player's rows
  away from another is RLS, proved by `node scripts/check-rls.mjs` (14 checks, two real users,
  run it **against the hosted project**, not only a local stack). The `service_role` key and the
  database password live in `.env.local` and reach nothing else — `test/headers.test.ts` fails if
  either name appears anywhere under `web/`.
- **`supabase/config.toml` is the source of truth for Auth, and `supabase config push` applies it.**
  Site URL, the redirect allow-list and the Google provider are all in there, with the client id and
  secret read as `env(...)`. Changing them in the dashboard by hand puts the repo and the project out
  of step, and the next `config push` silently reverts it.
- **`vercel.json` is generated, never hand-edited.** `SUPABASE_URL=… node scripts/build-headers.mjs`
  writes it and the result is committed, because Vercel reads it before the build command runs. The
  same variable feeds the bundle through esbuild's `define`, so the origin is set in one place.
- Sign-in is a **full-page redirect**, and that is load-bearing: `Cross-Origin-Opener-Policy:
  same-origin` severs a popup from the window that opened it and the flow never reports back, with
  no error printed anywhere.
- A Google OAuth client **caps at two client secrets and offers no way to delete one** — only to
  disable it. Rotating past that cap means deleting the whole client and creating a new one, which
  costs re-entering the redirect URI and updating the client id. Google keeps a deleted client
  restorable for 30 days.
- **The whole app sits behind sign-in (#39, user decision 2026-09-05, reversing #31's "anonymous stays
  identical").** `<body data-auth>` carries the state — `pending` (HTML default, shows neither side so
  nothing flashes), `out` (the entrance only), `in` (the app), `open` (a build with no `SUPABASE_URL`,
  which has no gate to open and behaves as before). `gate()` in `web/account.ts` sets it from the
  same supabase-js listener that reports the exchanged `?code=` session, and `web/styles.css` does the
  showing. The entrance carries the ONE sign-in button; the header shows only name + Sign out.
  `test/headers.test.ts` pins the single button and the pending default.
- Adding a redirect URI can take Google "5 minutes to a few hours" to apply. Do not debug it blind:
  `curl -sL "$(curl -s -o /dev/null -w '%{redirect_url}' 'https://<ref>.supabase.co/auth/v1/authorize?provider=google&redirect_to=https%3A%2F%2Friftcombo.app')"`
  answers `redirect_uri_mismatch` until it is live and the Google sign-in page after.
