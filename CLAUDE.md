## Workflow — GitHub issues are the backlog
- Every task the user names becomes a GitHub issue. Create it immediately with `gh issue create`, don't batch them up.
- Labels: `de-clone`, `ui`, `bug`, `data`, `legal`, `infra`. Reuse them; only add a new label when none fits.
- An issue body states what is wrong, the measured evidence, the files involved, and its dependencies on other issues. No vague one-liners.
- Close issues from commit messages (`Closes #4`) so the backlog does not drift from the code. Qualifying it does NOT scope it: `Closes #23 for web/main.ts` still closed all of #23 on push, and its second half had to be reopened by hand. When a commit does part of an issue, write `Refs #23`.
- `tasks/todo.md` is scratch for the current session only. GitHub issues are the durable backlog.

## Data
- Card text comes ONLY from Riot's gallery content API via `scripts/build-cards.mjs`; never from RiftScribe or other mirrors (they drop Equipment `effect` text and have no ban data).
- Errata is a dated overlay in `data/errata.json`; the build must fail if a find-string stops matching exactly once per printing. The one tolerated exception is a reprint that already carries the new text (Sona VEN-SP2, Void Burrower SFD-243): the build skips it. Riot's gallery API lags its errata pages by months, so after each Riot errata post, transcribe it into the overlay (audit of all four pages done 2026-09-03, #17).
- Legality is hand-transcribed from Riot's Rules Hub into `data/legality.src.json` (names) and resolved to codes at build time; it is format-scoped and entity-typed, never a boolean on the card.
- Match cards on base codes (`OGN-212`), never on names. Names are only for parsing pasted decklists.
- Card `type` is exactly one of `unit`, `spell`, `rune`, `gear`, `legend`, `battlefield`. **Equipment is not a type** — it is `gear` carrying the `Equipment` tag, so any filter on `type == "Equipment"` returns zero rows silently. Tags ride on every card in `cards.json` (`tags: string[]`) as well as in `data/corpus_flat.txt`, and a synergy predicate can stand on them alone — `Mega-Mech` is a Mech with no rules text. Two helpers (`UNL-T04 Buff`, `UNL-T08 XP Tracker`) carry an empty `type`.
- All 94 legends are named as bare epithets in the gallery (`Deceiver`), while Riot's own errata pages and players write `LeBlanc, Deceiver`. `resolveName` therefore retries on the text after the first comma, and `normalizeName` accepts both `- Starter` and `, Starter`. Verified 2026-09-04: no card name collides with another card's `X, Y` suffix, so the fallback can only rescue, never mislead.
- Base codes are NOT all `SET-NNN`: 22 are `SET-T0n` tokens, `SET-R0n` runes and `VEN-SP1`–`SP6`, and those last six are real playable cards (Kai'Sa, Sona, Ahri, Sett, Ezreal, Lux). A regex like `^[A-Z]{3}-\d{3}$` drops them silently; the shape that works is `[A-Z]*\d{1,3}[a-z*]?` and the `*` is load-bearing — 45 printings are alt-arts whose code ends in `*`. Audited 2026-09-04 (#14): every code regex in the repo was run against all 1189 codes, and the one failure was the TTS line guard in `src/deck.ts`, which used `[a-z]?` and so lost EVERY code on any dump line containing an alt-art.
- Anomalies in Riot's own text (bracket-less keywords, a dangling `[Effect] 1`, wrong tags, double periods) are REGISTERED in `docs/data-anomalies.md`, never normalised. They must never go into `data/errata.json`: that overlay's find-string failure is the only mechanism keeping our text honest, and spending it on a cosmetic typo would hide the next real errata behind it. What IS ours to fix is the HTML decoding in `stripHtml` — Riot ships `p`/`br`/`ul`/`li` and `&gt;`/`&quot;`, and two decoding gaps (undecoded `&quot;` on 12 cards, modal `<li>` modes glued into one clause on 15) were fixed on 2026-09-04.
- **Deck construction (#43, 2026-09-06) — three data facts a builder cannot derive from the code.** Riot's gallery carries NO Signature marker (0 hits in `cards_full.json`, no tag), so 103.2.d (max 3 Signature cards) is not computable and 103.2.a.2 cannot exclude a Signature unit as Chosen Champion; `checkBuild` therefore reports `pass | fail | unknown` per rule, never a boolean, and the Signature row shows as unchecked instead of being invented. The champion tag IS derivable: a tag T is a champion tag when a card named `T, <epithet>` exists — all 127 legend printings yield exactly one, including the four with 2–3 tags (VEN-155 Yordle + Kennen → Kennen); pinned by a test over the whole pool. And 103.2.b (3 copies) is a MAIN DECK rule: 103.3.b keeps the Rune Deck apart and 103.4.c covers battlefields, so counting runes against it declares EVERY legal deck illegal (six Mind Runes). The nine rules are quoted verbatim in `docs/phase0/walks/2026-09-06-deck-construction-rules.md`.
- Tokens, runes and the two typeless helpers stay in `data/corpus_flat.txt` on purpose: 79 corpus lines tell you to play a token without printing what it does, and rule 187 plus the token's own row is the lookup a rules walk needs (the R25 ruling turned on `UNL-T05 Gold`'s text). An empty `type` renders as `-`, not as a blank column.

## Combos
- `data/combos.json` is AUTHORED. `status: verified` requires a hand-walked loop against card text + Core Rules with sources; agent output enters as `candidate` until a human reviews it.
- Every combo carries a class: INFINITE (walked, unbounded), BURST (**one** scoring event reaches 8), CHAIN (reaches 8 across **several** scoring events, without the opponent taking a turn in between), ALT_WIN (a card that literally says you win), or ENGINE. Never label INFINITE without a "repeat" step. CHAIN was added 2026-09-04 (issue #20) for the three Time-Warp-chained and double-Conquer finishers that reach 8+ but not in one event: labelling them ENGINE would have been false, since they win. The class is a plain string in the UI (`c.class.replace("_", " ")`), but it is typed in `src/types.ts` and ranked in `src/combos.ts` CLASS_RANK plus the sort orders in `web/graph.ts` and `web/main.ts` — all five must be updated together.
- Do not accept structural verdicts from agents ("no X exists in the pool") without walking the validation set first; the first hunt's "no infinite combos" was wrong.
- Authoring traps the 2026-09-03 REFUTE passes caught repeatedly, check every new entry against them: entering an EMPTY enemy battlefield is not an attack (Assault and "When I attack" need the Attacker designation, which exists only inside a Combat with a garrison: 807.1.d, 383.4.e, 461); Energy added in Awaken or the Beginning Phase is lost when the Rune Pool empties at the Main Phase start (167); a Repeat gives no window to re-exhaust a resource permanent between executions (429.3, R21); Temporary tokens die before Scoring, so they never Hold and never see a Main Phase start (816.1.b) — but that trap does NOT stop a Temporary body being COUNTED by an ability that fires at the same instant, because 816.1 makes Temporary a Triggered Ability and 383.3.d lets the player controlling both abilities order them (settled 2026-09-04 for `gutter-palace`, which had it filed as an open reading); Gold tokens are printed "exhausted", but Renata Industrialist overrides that and they enter ready (R25 = A); recycling a rune for Power sends it to the Rune Deck (161.2.b), so Ekko readies only what is still on the board; a recall is not a move (456) and does not change state (458). A `would die` shield of the heal / exhaust / recall family ERASES the Deathknell of what it saves: 808.1.d.1 removes the triggered ability from the chain when the permanent never reaches the Trash (found 2026-09-06 on `soraka-fiora-loop-shield`, whose replacement has no `may`, so it also switches off the Deathknell of any friendly body under 4 Might that dies at the base).
- A BURST entry must reach 8 **with the quantities it declares**, and the class must match `terminatesIn`. Check the entry's own formula against its own `uses` before authoring or promoting: the 2026-09-04 audit of all eleven BURSTs found four that failed this. `ahri-blue-sentinel-hold`, `blue-sentinel-trinity-force-hold` and `ivern-sentinel-hold` each declared a board their own printed formula resolves to 7; `tryndamere-brambleback-conquer` declared one worth 4, which its own REFUTE note had already flagged in 2026-09-03 without the fix ever being applied; and `renata-time-warp-ekko-refresh` claimed BURST while its own `terminatesIn` described points spread over two turns (reclassed ENGINE). A REFUTE verdict in `notes` is not a fix — grep for corrections that were diagnosed and never applied.
- Recycle budget is the real currency of an INFINITE loop, not the 3-copy deck limit. Recycle (416.1) puts cards on the BOTTOM OF THE DECK, so a spell consumed every pass is fine as long as the entry can name the recycle slot AND the matching draw that bring it back. The verified `lux-infinite-energy` engine saturates its 4 draws per pass and leaves EXACTLY ONE spare Forge recycle slot (Forge recycles 3 of its 4; Ekko's Deathknell recycles itself). REFINED 2026-09-04 by the joint ledger on issue #21 (`docs/phase0/walks/2026-09-04-loop-budget-ledger.md`): the scarce resource per pass is **draws, not slots**. Both pass types leave spare slots and ZERO spare draws — the Energy pass leaves 1 slot, and `lux-infinite-power` is a second, different pass that leaves 2. And the draw is purchasable: Renata Mastermind's `1 Energy + 1 Mind: Draw 1` carries NO exhaust in its cost (unlike her Score ability beside it), so extra draws are unlimited and an extra cycled card costs 1 Energy + 1 Mind Power ≈ 10 Energy at the 9-Energy-per-Power rate. No payoff in the catalogue consumes a card per PASS; they consume one per point, and a point costs ~50 passes, so ~50 spare slots accumulate per point. The three Renata routes are alternatives because they all do the same job (ready Renata to score again), not because the engine cannot feed two. Do not re-derive any of this as a copy-limit bound. **Equipment that copies text COMPOSES, it does not add** (settled 2026-09-06 on #45): 434.1.c gives the Top-Most Card ALL the Effect Text of ALL its attached cards; 477.2.c appends that text in Layer 2, 479.1 finds no dependency between two copies that each alter the other, 480.3 falls back to timestamp order (attach order), and 476.1 applies each effect only once across all sequences — so v Svellsongur on one unit yield 2^v instances, not 1+v, and 476.1 is why R6 = A opens no recursion. `svellsongur-copy-hold` went from 11 to 17 points on the same five cards and its ceiling from 26 to 41. Companion fact from the same walk: an ability worded `When I conquer or hold` is BOTH a Conquer Effect and a Hold Effect (823.1.b, 823.1.c.1 spell it out for Hunt), so Reckoner's Arena doubles it twice — `ivern-arena-sentinel-hold` reaches 9 for 20 Energy + 2 Power. Always count the [Equip] costs and the Power: two published "18 Energy" figures had counted neither. **A legend is not at a location** (107.4.b: the Legend Zone "is not a location"), so Reckoner's Arena's "here" and Svellsongur's attach never reach a legend's own `When you conquer` text — the whole "legend + Arena" family is dead on arrival (#47, 2026-09-06). And 206 / 206.1 make cost-triggered abilities (Lady of Luminosity, Curator of the Sands — both are the worked examples) fire on the PRINTED or BASE cost, so discounts and free plays do not switch them off. **Tokens are born at the base, and points are scored at battlefields** (#48, 2026-09-06): of the 49 cards that create unit tokens, 18 say "at your base" outright, 13 say "here" (a battlefield), and 18 name no destination (355.2.a: base, or a battlefield you control). Exactly ONE card in the pool relocates tokens in bulk — `SFD-177 Azir, Sovereign`, "When I attack, you may move any number of your token units to this battlefield" — so the bottleneck of every token line is the walk to the battlefield, not the token count. And there is NO window to add a body at the instant of the Hold: 315.2.b.2 puts the Hold in the Scoring Step of the Beginning Phase, 312.2.a gives priority only in the Main Phase, and 383.2.a.1 measures the condition when the trigger is placed — the seven for the Plaza must survive the opponent's whole turn. **Ready lens (#56, 2026-09-06):** "enters ready" is not a ready — 143.4 makes units enter exhausted and 415.1 defines Readying as marking a Game Object already on the board, so the 48 "enters ready" cards can never give an exhaust back; only 16 cards in the pool ready something other than themselves. A legend IS on the board (107.4.c, "The Champion Legend here is a Game Object") even though it is not at a location (107.4.b), so readies reach it: four cards ready your legend (SFD-039, SFD-210, OGN-111 via Heimerdinger's copy, OGN-162 Miss Fortune). Five cards ready gear (VEN-149, VEN-150, SFD-221, OGN-162, VEN-068) — a `grep` that swallowed an adjective once published "the ONLY card that readies gear" inside a verified entry; when a note claims uniqueness, grep the whole pool with `-i` and the bare word before shipping it. REFINED AGAIN 2026-09-06 by the #44 walk: **every deck has a free floor of 2 Power per turn**, so measure any new Power source against it, not against zero — 164.2.b (`Recycle this: [Reaction] — Add [C]`) carries no exhaust, so a rune already exhausted for Energy still recycles for Power; 161.2.b sends it to the Rune Deck, not the Main Deck; and 315.3.b / 430.4.a channel 2 back every Channel Phase before the Main Phase. The "12 recycles per game" ceiling #44 assumed does not exist. Seals produce per TURN and loops spend per PASS, so the ~9 Energy per Power rate for a loop stands. The extra cycled card costs 4 Energy instead of ~10 only when a Forge recycle slot is spare (Forge is `Recycle up to 4`), which only the Power pass guarantees: the Energy pass has one spare slot and the card itself eats it. **Exception, found 2026-09-06 on the Dragonstorm ledger (#46):** `SFD-117 Ancient Henge` — `exhaust: [Reaction] — Pay any amount of Energy to [Add] that much rainbow` — converts Energy to Power 1:1 with NO cap per activation, so a loop that re-plays a Henge every pass (Detonate kills it, Vi recycles it, Show of Strength draws it back; gear enters ready since 143.4 exhausts only units) makes Power stop being the scarce currency: its ledger is Energy-only, and the ~9 Energy per Power rate does not apply to it. The Henge is E2 P1, so the FIRST pass must be primed with the Power the conversion will later supply.
- Before filing a new numbered rules reading, try a different LEGAL ORDERING of the same cards first — reorder the chain, resolve before responding, pick a different target, split one window into two. `grand-plaza-loop-time-warp` was blocked on a mistarget reading (filed as R29, 2026-09-04) that vanished once Shadow's Call was simply resolved before Sacrifice instead of in response to it; `813.1.b` gives Reaction every permission of Action, so a Reaction spell never has to be a response. An entry that stands on sequencing beats one that stands on an unruled interpretation, and every reading filed is a question the user has to answer.
- Sources carry their evidence: a `Source` may hold `quote` (the verbatim passage the entry stands on) and `accessed` (the date somebody on this project opened the url and read it there). Fill both whenever you open a page. The 2026-09-04 audit read the two TCGplayer articles end to end and confirmed 9 of 9 citations, but it also found three entries pointing at `infinite.tcgplayer.com/article/...`, which answers 200 to a HEAD and serves a CAPTCHA wall; the readable form is `www.tcgplayer.com/content/article/...`. Ask a reader proxy for the WHOLE page, never a keyword extract — a narrow prompt once made a session call a real quote fabricated.
- **Reddit is closed to this machine as of 2026-09-06.** The 2026-09-04 route (`old.reddit.com` + in-page `fetch` of `.json`) died first ("accounts are required to access old Reddit"); the morning-of-2026-09-06 route (`www.reddit.com` `.json` through the browser's request context) died within hours; by the afternoon curl, r.jina.ai, headless Playwright, HEADED Chrome with the MCP profile's cookies, and the redlib/safereddit mirrors all answer 403 or a "Prove your humanity" CAPTCHA — the one case where the browser rule stops. So a Reddit thread is citable only if the user opens it and pastes the text; otherwise verify the CLAIM against the corpus and Core Rules and cite that instead (stronger evidence anyway). The sub is `r/riftboundtcg`. #46 reports a community list of infinites in thread `1ryj4fw` — unread, treat as a lead. YouTube IS readable without login: `yt-dlp --skip-download --write-auto-sub` on `ytsearchN:` queries gives titles and transcripts; #46 read 37 of them, and a video is cited with URL + timestamp + the subtitle line.
- A community deck NAME is not a claim you can walk. Issue #16's candidate #9 was "Viktor infinite without the banned Stealthy Pursuer"; the actual Rift Mana list is `garen-fiora-malzahar-facebreaker-recruits` card for card, predates the ban by five months, and never held Pursuer. Read the decklist before believing a description of it — and when a community report contradicts itself on domain identity (the RQ Vancouver Gutter Palace report names both a Jhin legend and a Chaos card), record the discrepancy instead of picking a side.
- Riftbound is not MTG: no life total, win at 8 points, infinite draw is a liability (Burn Out), units enter exhausted, Rune Pool empties each turn, Domain Identity is subset-of-legend and every Legend has exactly two domains.

## Synergies (#22)
- `data/synergies.json` is a SEPARATE file and must stay separate. `combos.json`'s whole value is that every row in it was walked by hand; a text-matched row in there destroys that invariant.
- The unit is a PATTERN: one `anchor` base code plus a `partner` predicate over the pool. The rule is hand-verified once and carries `basis.rules` (Core Rules paragraphs), optional `basis.readings` (R-numbers from issue #11) and `basis.combos` (the verified entries it was extracted from). The instances are text matches. **Regla verificada, instancias por texto** — the UI says so in its own words and never presents a pair as a combo.
- **Print the whole match list and read it before shipping a rule.** `npm run synergies` prints every list, `-- --match` prints only the fragment each predicate caught, `-- <id>` narrows. A rule whose list you cannot read end to end is written too loosely; `test/synergies.test.ts` caps a rule at 150 matches for that reason.
- What the predicates are allowed to lean on: 383.4.c.1 and 383.4.d.1 give `"When I conquer…"` / `"When I hold…"` as the standard wording of those trigger categories, and 823.1.b makes [Hunt] both. That is why the hold and conquer predicates are honest rather than guesses.
- False positives found by reading the lists, and the shapes they come in — check any new rule against all four: a **nested quote** (Relentless Pursuit and Zed, From the Shadows carry a trigger written for another permanent inside their own text); a **second trigger that is a no-op** (Blitzcrank returns himself to hand, Hallowed Tomb needs an empty Champion Zone); a **doubled drawback** (Vaults of Helia, Sigil of the Storm); and a **condition that cannot be met on the other event** — 383.4.g.1 says an ability whose non-conquer parts are unfulfilled never reaches the chain, which is what kills Tryndamere, Sivir, Yeti Brawler, Yone and Swain under Reckoner's Arena. Record each as an `excludes` entry with its reason; never drop one silently.
- Tokens and the two helper cards are filtered out of every list (`domains.length === 0 && !type.includes("battlefield")`), since a decklist can never hold one. An anchor banned in every format fails validation — that is how `stealthy-pursuer-move-triggers` was caught.
- **A keyword lens opens with `grep -i <word>`, never with `[Keyword]`.** The bracketed form misses
  every card that writes the mechanic in prose: 8 cards say `empower`/`disempower` in lower case with
  no brackets and 4 of those are legends, so a `\[Empower\]` sweep silently skipped the legends of
  the family it was hunting (#34, 2026-09-05). Open wide with `-i`, then close by reading the list.
- **A battlefield you provide starts UNCONTROLLED, so its text is off until you take it.** 190.1:
  *"Control is established over Battlefields through the course of play."* 190.6.d closes it: *"If the
  battlefield has no Controller, 'you' refers to no one, and all such instructions are ignored."* The
  project had cited 190.6.d for R8 but never its second sentence. So a `While you control this
  battlefield` discount is NOT a deckbuilding freebie — walking a body there and establishing Control
  (466.5) is part of the entry's cost. Six battlefields print that wording; only SFD-211 Marai Spire
  is in the catalogue, and `ezreal-marai-spire-free-repeat` says so in its own notable (2026-09-05).
- **A battlefield is drawn at random, and only in some formats, and you cannot stack copies of it.** 485.4.a: a
  player provides three and only 1 is used; **485.5 and 487.5 say "randomly selects"**, while **486.5 says only
  "selects"**. So two of your battlefields never share a board (#33 fixes the synergy layer on this), and a
  battlefield-dependent combo is not certain to come online. Bringing 3 copies of the same battlefield is NOT a
  way out: **Core Rules 103.4.c** ("Cannot include more than one of a Battlefield of the same name when there
  are more than one required for the deck") and **Tournament Rules 402.1** ("exactly 3 battlefields each with a
  unique name") both forbid it. Issue #35 (2026-09-05) was opened believing the Core Rules were silent on this;
  they are not — 103.2.b is the Main Deck cap, the battlefield cap is three paragraphs further down. Every entry
  that needs a specific battlefield states this in `prerequisites.notable`, per format.
- A rule that matches most of the pool is a fact about the pool, not a pairing. "Retreat replays any play effect" measured 132 and was narrowed to play effects that leave another permanent behind (14).
- UI lives in the deck panel **below** "What to add", so #18 keeps the placement the user chose.

## Legal posture
- No ads, no donations, no meta stats (play/win rates), no combo *execution*, exact Riot disclaimer text from `docs/plan.md` §1.
- **Do not copy LOOPLINE.** It is the reference for *what a combo route map does*, never for how it looks or what it calls things. Copying its colour tokens, wordmark lockup, nav labels, headings or column labels is out of bounds — the 2026-09-02 build did exactly that and had to be reworked (issues #1–#3).
- Before shipping any UI string, check it is not lifted verbatim from the reference.

## UI — visual identity
- Palette (from playriftbound.com, not from LOOPLINE): bg `#0f1a1e`, panel `#1E3043`, panel-alt `#293a4c`, rule `#336073`, text `#f9eedc`, muted `#8fa7b3`, accent `#EF7D00`.
- One type family: Inter. Hierarchy comes from size and weight, never from a display face. Cinzel (the Trajan analog) was tried on 2026-09-03 and rejected by the user as poster-like and illegible at diagram sizes — do not reintroduce a serif or display face.
- Corners are rounded: containers 10px, controls 6px, diagram nodes 9–10px. Sharp 2–3px corners were tried and rejected as "too square". The diamond motif lives on the brand mark only; status dots and swatches are circles.
- Battlefields are printed landscape (`orientation: "landscape"` in cards.json, 66 printings). Any card rendering must honour that or the art gets cropped and the text stands on end.
- Domain colours are reserved and must not be reused for anything else: Fury `#ce212d`, Calm `#15ac72`, Mind `#22799c`, Body `#e4720c`, Chaos `#6c4993`, Order `#d0ab01`.
- One accent. Outcome classes read through text and weight, not through a categorical rainbow.
- No emoji, no blue/purple gradients, no decorative shadows, no glassmorphism.
- Hand-rolled SVG graph — no graph library.
- The **What to add** panel (#18, 2026-09-04) lives in the deck panel under the status card, not as a third view segment and not as a separate page — the user chose that placement over both. Its logic is `src/plan.ts` (`planDeck`), kept out of `web/` so it has tests. Three rules the user set and that must not be quietly reversed: it ranks by **copies to add**, with the combo class only breaking a tie; it shows the cheapest route **whatever it costs** — a six-card route is still displayed, because the count itself is the honest signal and hiding it hides a real answer; and it never suggests a card outside the legend's two domains (Domain Identity 103.1.b), which `test/plan.test.ts` pins against the mono-Fury fixture. It also drops any line whose ingredients are banned in the format being matched, so the panel never recommends buying an illegal card even when the matcher correctly reports the hit.
- The **Banned and restricted** panel (#23, 2026-09-04) is the first thing in the deck panel, above the status card, because a list brought to a tournament wants that before any combo. `deckRestrictions(deck, cards, format)` in `src/deck.ts` takes the format rather than storing a flag on the parse, so the panel re-reads on the format toggle. `banned` and `restricted` are NOT the same thing and must not render the same: restricted is a cap, not an illegal card, and `OGS-019` is restricted in 2v2 only.
- The panel answers only what is computable. The narrative half of a hunt entry ("Svellsongur on Hwei fires twice per move") came from an agent reading card text and is NOT derivable from `combos.json`; "Already in this list" therefore means catalogued lines the deck completes plus catalogued pieces it holds, and nothing is invented to fill that section.

## Web gotchas
- CSP forbids inline `style=`: colour SVG through attributes, and HTML through CSSOM (`el.style.x = …`).
- `wrangler.toml` needs `run_worker_first = true` or the security headers never apply to static files.
- `[hidden]` needs `display:none !important` because `.empty` sets `display:grid`.
- Playwright MCP can only write screenshots into `.playwright-mcp/` (gitignored).

## Accounts (#31)
- **The site lives at `https://riftcombo.app`** (bought through Vercel on 2026-09-05, #42; renewal US$15/yr,
  Vercel nameservers). `www.riftcombo.app` and `riftcombo.vercel.app` answer 308 to the apex, and that
  redirect is a **project-domain setting** (`PATCH /v9/projects/<id>/domains/<host>` with
  `{"redirect":"riftcombo.app","redirectStatusCode":308}`), not a `vercel.json` rule: a host-matched
  `redirects` entry in `vercel.json` was tried first on 2026-09-05 and never matched on a Git deploy.
  The old host stays in the Supabase redirect allow-list; every link, `site_url` and doc names `.app`.
- The hosted Supabase project is `bpbwsimgiyxzaorunqeo` in `us-east-1`, the region iad deploys to.
  Its **anon key is public by design** and rides in `public/app.js`; what keeps one player's rows
  away from another is RLS, proved by `node scripts/check-rls.mjs` (14 checks, two real users,
  run it **against the hosted project**, not only a local stack). The `service_role` key and the
  database password live in `.env.local` and reach nothing else — `test/headers.test.ts` fails if
  either name appears anywhere under `web/`.
- **`supabase/config.toml` is the source of truth for Auth, and `supabase config push` applies it.**
  Site URL, the redirect allow-list and the Google provider are all in there, with the client id and
  secret read as `env(...)`. Changing them in the dashboard by hand puts the repo and the project out
  of step, and the next `config push` silently reverts it.
- **`vercel.json` is generated, never hand-edited.** `SUPABASE_URL=… node scripts/build-headers.mjs`
  writes it and the result is committed, because Vercel reads it before the build command runs. The
  same variable feeds the bundle through esbuild's `define`, so the origin is set in one place.
- Sign-in is a **full-page redirect**, and that is load-bearing: `Cross-Origin-Opener-Policy:
  same-origin` severs a popup from the window that opened it and the flow never reports back, with
  no error printed anywhere.
- A Google OAuth client **caps at two client secrets and offers no way to delete one** — only to
  disable it. Rotating past that cap means deleting the whole client and creating a new one, which
  costs re-entering the redirect URI and updating the client id. Google keeps a deleted client
  restorable for 30 days.
- **The whole app sits behind sign-in (#39, user decision 2026-09-05, reversing #31's "anonymous stays
  identical").** `<body data-auth>` carries the state — `pending` (HTML default, shows neither side so
  nothing flashes), `out` (the entrance only), `in` (the app), `open` (a build with no `SUPABASE_URL`,
  which has no gate to open and behaves as before). `gate()` in `web/account.ts` sets it from the
  same supabase-js listener that reports the exchanged `?code=` session, and `web/styles.css` does the
  showing. The entrance carries the ONE sign-in button; the header shows only name + Sign out.
  `test/headers.test.ts` pins the single button and the pending default.
- Adding a redirect URI can take Google "5 minutes to a few hours" to apply. Do not debug it blind:
  `curl -sL "$(curl -s -o /dev/null -w '%{redirect_url}' 'https://<ref>.supabase.co/auth/v1/authorize?provider=google&redirect_to=https%3A%2F%2Friftcombo.app')"`
  answers `redirect_uri_mismatch` until it is live and the Google sign-in page after.
