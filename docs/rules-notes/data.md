# Data notes

> Moved verbatim from `CLAUDE.md` by #274 (2026-10-06). Read before touching `scripts/build-cards.mjs`, `data/errata.json`, legality, code resolution or deck construction.

## Data
- Card text comes ONLY from Riot's gallery content API via `scripts/build-cards.mjs`; never from RiftScribe or other mirrors (they drop Equipment `effect` text and have no ban data).
- Errata is a dated overlay in `data/errata.json`; the build must fail if a find-string stops matching exactly once per printing. The one tolerated exception is a reprint that already carries the new text (Sona VEN-SP2, Void Burrower SFD-243), and it is named per printing in the errata entry's own `alreadyReprinted` field — never inferred from content, since a coincidental match of the replace-string must not be able to disguise a mistyped find-string (#136). The build still requires the replace-string to be present on a listed printing, failing by name otherwise, and fails any unlisted printing whose find-string is already gone. Riot's gallery API lags its errata pages by months, so after each Riot errata post, transcribe it into the overlay (audit of all four pages done 2026-09-03, #17).
- Legality is hand-transcribed from Riot's Rules Hub into `data/legality.src.json` (names) and resolved to codes at build time; it is format-scoped and entity-typed, never a boolean on the card.
- Match cards on base codes (`OGN-212`), never on names. Names are only for parsing pasted decklists.
- Card `type` is exactly one of `unit`, `spell`, `rune`, `gear`, `legend`, `battlefield`. **Equipment is not a type** — it is `gear` carrying the `Equipment` tag, so any filter on `type == "Equipment"` returns zero rows silently. Tags ride on every card in `cards.json` (`tags: string[]`) as well as in `data/corpus_flat.txt`, and a synergy predicate can stand on them alone — `Mega-Mech` is a Mech with no rules text. Two helpers (`UNL-T04 Buff`, `UNL-T08 XP Tracker`) carry an empty `type`.
- All 94 legends are named as bare epithets in the gallery (`Deceiver`), while Riot's own errata pages and players write `LeBlanc, Deceiver`. `resolveName` therefore retries on the text after the first comma, and `normalizeName` accepts both `- Starter` and `, Starter`. A third retry (2026-09-06, #86) handles Riot's own inconsistency: the same champion is printed with two heads — `OGS-004 Yi, Meditative` / `OGS-009 Yi, Honed` in the starter, `UNL-059 Master Yi, Unstoppable` / `UNL-113 Master Yi, Tempered` in Unleashed — and the "Top Decks" articles write the long head for all four, so `resolveName` retries with the last word of the head + the epithet, ONLY when the head is a tag the pool prints (eleven tags are multi-word; `Master Yi` is the only one whose last word heads a name). Verified 2026-09-04: no card name collides with another card's `X, Y` suffix, so the fallback can only rescue, never mislead.
- Base codes are NOT all `SET-NNN`: 22 are `SET-T0n` tokens, `SET-R0n` runes and `VEN-SP1`–`SP6`, and those last six are real playable cards (Kai'Sa, Sona, Ahri, Sett, Ezreal, Lux). A regex like `^[A-Z]{3}-\d{3}$` drops them silently; the shape that works is `[A-Z]*\d{1,3}[a-z*]?` and BOTH suffixes are load-bearing — 45 printings are alt-arts whose code ends in `*` and 102 end in a lower-case `a`; the two families coexist. Any normalisation must be CASE-INSENSITIVE end to end: until 2026-09-06 (#87) `resolveCode` upper-cased the input and then `baseOf` trimmed with a case-sensitive `/[a-z*]$/`, so `UNL-113a`, `UNL-113A` and `ogn-007a` all failed — 306 of the 3,567 spellings of the pool's own codes were being dropped, including Riot's gallery spelling; a test now sweeps all 1,189 codes in three spellings. riftbound.gg writes the alt-art suffix in upper case (`UNL-113A`). Its full dialect (#90, 2026-09-06, measured on 452 lists / 12,150 lines): `-STAR` is exactly the 45 alt-arts the gallery writes with `*` (one to one, normalised to `*`); `-P`, `-P2`, `-P-Champion` are PROMOS (promo=1 in dotgg's index: Nexus Night, Judge, Release Event, Summoner Skirmish) that Riot's gallery does not carry at all, so they resolve to the base code; `OGN-263-a` is the one id that hyphenates the variant letter. And **runes are printed only under Origins and reprinted in Vendetta — there is no `SFD-R0x` or `UNL-R0x` in the gallery**, so a Spiritforged or Unleashed rune line is an alias in `RUNE_ALIAS` (`src/cards.ts`), verified by name (R01 Fury, R02 Calm, R03 Mind, R04 Body, R05 Chaos, R06 Order in all three sets), not a suffix to normalise; without the Unleashed row a list lost its whole rune deck (696 of 775 rune lines). Before: 1,154 lines lost; after: 0. Audited 2026-09-04 (#14): every code regex in the repo was run against all 1189 codes, and the one failure was the TTS line guard in `src/deck.ts`, which used `[a-z]?` and so lost EVERY code on any dump line containing an alt-art.
- Anomalies in Riot's own text (bracket-less keywords, a dangling `[Effect] 1`, wrong tags, double periods) are REGISTERED in `docs/data-anomalies.md`, never normalised. They must never go into `data/errata.json`: that overlay's find-string failure is the only mechanism keeping our text honest, and spending it on a cosmetic typo would hide the next real errata behind it. What IS ours to fix is the HTML decoding in `stripHtml` — Riot ships `p`/`br`/`ul`/`li` and `&gt;`/`&quot;`, and two decoding gaps (undecoded `&quot;` on 12 cards, modal `<li>` modes glued into one clause on 15) were fixed on 2026-09-04.
- **Deck construction (#43, 2026-09-06) — three data facts a builder cannot derive from the code.** Riot's gallery carries NO Signature marker (0 hits in `cards_full.json`, no tag) — `checkBuild` therefore reports `pass | fail | unknown` per rule, never a boolean, for rules the card data cannot see. 103.2.d (max 3 Signature cards) and the Signature half of 103.2.a.2 stopped being two of those on 2026-09-06 (#103): two independent mirrors (Piltover Archive's `card.super`, dotgg's `supertype`) agree on the same 51 names, transcribed by name into `data/signature.src.json` and resolved to exactly one base code each in `scripts/build-cards.mjs`, which fails the build on a name resolving to zero or 2+ bases; `Card.signature: boolean` rides in `cards.json`. `checkBuild` now scores 103.2.d.1 (≤3 total, regardless of name — checked even with no legend, since it does not need one), 103.2.d.2 (each carries the legend's champion tag) and 103.2.d.3 on the Chosen Champion (a Signature card, even one whose tag matches, can never be Chosen Champion — Tibbers is the rule's own worked example). The champion tag IS derivable: a tag T is a champion tag when a card named `T, <epithet>` exists — all 127 legend printings yield exactly one, including the four with 2–3 tags (VEN-155 Yordle + Kennen → Kennen); pinned by a test over the whole pool, which also pins the 51 Signature base cards and their one champion tag each. And 103.2.b (3 copies) is a MAIN DECK rule: 103.3.b keeps the Rune Deck apart and 103.4.c covers battlefields, so counting runes against it declares EVERY legal deck illegal (six Mind Runes). The nine rules are quoted verbatim in `docs/phase0/walks/2026-09-06-deck-construction-rules.md`.
- Tokens, runes and the two typeless helpers stay in `data/corpus_flat.txt` on purpose: 79 corpus lines tell you to play a token without printing what it does, and rule 187 plus the token's own row is the lookup a rules walk needs (the R25 ruling turned on `UNL-T05 Gold`'s text). An empty `type` renders as `-`, not as a blank column.
