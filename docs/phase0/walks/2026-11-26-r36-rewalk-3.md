## The reading: R36 = B on the 2026-10-09 text

Svellsongur's sentence is a copy effect, and the 2026-10-09 rules name it as one in the copy layer, the
first:

> **479.1.d** Effects for this layer can be identified by the phrase "copy" in the text. Example: Svellsongur is an Equipment that reads in part “As this is attached to a unit, copy that unit's text to this Equipment's effect text for as long as this is attached to it.” This is a copy effect that is applied in this layer.

A copy reads copyable traits, which are the printed traits. They are not the actual traits that later
layers modify:

> **479.1.b.1** The copyable traits of a Game Object are all of the printed—or if a copy effect is applied, copied—traits of that Game Object. In the case of a Token, they are the traits the token had when it was Created. Example: The copyable traits include the printed versions of the following traits: Name, Supertype, Type, Tags, Cost, Domain, Rules Text, Effect Text, Might, Might Bonus, Flavor Text, Art
>
> **479.1.c** Copyable traits of a Game Object are distinct from the actual traits of that Game Object, which may be modified by subsequent applied Layer effects.

The append of an attached card's Effect Text is a later layer. 479.3.c is 2026-07-16's 477.2.c word for
word. 479.3.a is 2026-07-16's 477.2.a with "Effect Text" added to its list, so both texts are below:

> 2026-07-16 **477.2.a** This layer deals with non-Copy effects that grant, remove, or replace the abilities or rules text of Game Objects. Keywords Passive Abilities Appending rules text Removing rules text

> 2026-10-09 **479.3.a** This layer deals with non-Copy effects that grant, remove, or replace the abilities or rules text of Game Objects. Keywords Passive Abilities Appending rules text Removing rules text Effect Text
>
> **479.3.c** Abilities of Effect Text of Attached cards are appended in this layer.

Each effect applies once, and the recurrence re-applies nothing already applied. 478.2 and 478.3 are
2026-07-16's 476.1 and 476.2 word for word:

> **478.2** Layers are applied in sequence. Each effect in them is applied as soon as able, and only a single time across all sequences.
>
> **478.3** When a sequence of applications completes, recur the process, and evaluate each layer again applying any effects that may now be applicable.

Ordering by Timestamp is within one Layer and Sublayer. 482.3 and 481.1 are 2026-07-16's 480.3 and 479.1
word for word:

> **482.3** Effects are applied such that the earliest Timestamp within each Layer and Sublayer applies first, followed by other Effects in that Layer and Sublayer in chronological order.
>
> **481.1** If both effects are altered by the application of the other, no Dependency can be established. Example: A unit with 4 [M] is under the effects of a passive ability that reads “Units you control here have their Might increased to 5 [M].” Its controller plays a spell that reads “Give a unit +2 [M], to a maximum of 5 [M].” If we apply the passive ability first, the passive ability will apply +1 [M] and the spell effect will apply +0 [M]. If we apply the spell effect first, it will apply +1 [M] while the passive ability applies +0 [M]. Both effects are altered by the sequence of applications, so we can’t establish a dependency.

The count, for a unit U wearing v Svellsongur S1 … Sv, with U's printed text T and no copy effect
applied to U itself:

1. In the copy layer each Si applies its copy effect once (478.2) and copies U's copyable traits. Those
   are the printed T (479.1.b.1). Si's copy changes Si's Effect Text and leaves U's copyable traits as
   they were, so no two copies alter each other: 481.1's no-dependency case never arises, and 482.3's
   Timestamp order gives the same result in every attach order.
2. In the ability layer each Si's Effect Text, now T, is appended to U's Rules Text (479.3.c, 435.1.c).
   U's actual Rules Text is T plus v copies of T: v + 1 instances.
3. The recurrence of 478.3 re-evaluates the layers, but 478.2 has already applied every Si's copy "only
   a single time across all sequences". The append changed U's actual traits, not its copyable traits
   (479.1.c), so a copy applied again would still read T.


The same steps drop two things a 2026-07-16 count could carry. **Another Equipment's Effect Text is not
copied**: it reaches U's actual Rules Text in the ability layer and never U's copyable traits. **A granted
keyword is not copied**, for the same reason: 479.3.a lists Keywords among that layer's grants. No entry in
this batch wears another Equipment or counts a granted keyword: each carries Svellsongur and nothing else,
and the keywords a copy carries below, Steel Paws' [Deflect] and [Empower], are printed on the unit. So in
this batch the change is the count alone: one Svellsongur gives 2 instances under both readings, and three
give 4, not 8.

The 2^v count was made on the 2026-07-16 layers, which put the copy and the append in one layer ordered
by Timestamp, so a later copy read the text an earlier copy had appended.
`docs/phase0/walks/2026-11-26-r36-rewalk-1.md` holds the same reading and its R6 note; this walk does not
repeat them.

Out of scope here: R36 itself (a doubt about it goes on #706), entries outside this batch, and the #703
batches. This walk did not read Riot's patch notes for the 2026-10-09 edition and cites none.
